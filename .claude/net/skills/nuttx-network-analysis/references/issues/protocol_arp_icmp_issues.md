## 1. ARP 解析失败

**特征**：网络不通，ARP 表中目标 IP 无对应 MAC

### 1.1 ARP 请求未发出

- 网络接口未 up
- 路由表无匹配条目
- 目标 IP 不在同一子网且无默认网关

### 1.2 ARP 响应未收到

- 物理链路问题（PHY link down）
- VLAN 配置不匹配
- 对端未响应 ARP 请求
- ARP 请求被过滤

### 1.3 ARP 缓存问题

- ARP 缓存表满
- ARP 条目超时过短
- 静态 ARP 条目配置错误

## 2. 大量 ARP 自学习后 ICMP 不回复

**特征**：大量陌生 IP/MAC 进行 ARP 自学习后，ICMP 请求全部不回复

**原理**：ARP 表被大量自学习条目填满后，新的 ARP 解析无法写入，导致后续通信失败。

**典型案例**：VELAFORCAR-15342

**排查思路**：
1. 检查 ARP 表大小配置是否足够
2. 确认 ARP 表是否被填满
3. 检查 ARP 表淘汰策略（LRU/超时）

## 3. ICMP 响应延迟过高

**特征**：ICMP 请求响应延迟远超预期（如 >100ms）

**原理**：ICMP 处理延迟通常指向调度延迟（高优先级任务抢占）而非协议栈处理延迟。

**典型案例**：VELAFORCAR-15364

**排查思路**：
1. 检查 ICMP 处理在哪个工作队列中执行
2. 检查是否有高优先级任务抢占了 ICMP 处理
3. 对比空载和满载下的延迟差异

## 4. ICMP 大包（1500字节）不回复

**特征**：大 payload 的 ICMP 请求不回复，小包正常

**原理**：大包可能超过单个 IOB 容量或超过 MTU，需要 IOB 链或 IP 分片支持。如果相关功能未配置则大包无法处理。

**典型案例**：VELAFORCAR-13927 / 13750

**排查思路**：
1. 检查以太网包大小限制配置
2. 检查 IOB 缓冲区大小——大 payload 加上协议头可能超过单个 IOB
3. 检查 IP 分片是否启用
4. 计算实际包大小是否超过 MTU

## 5. ARP 异常报文处理不合规

**特征**：对 Hardware Type/Protocol Type 为 Unknown 的 ARP 报文仍然响应或学习

**原理**：按照 RFC 标准，Unknown 类型的 ARP 报文应丢弃，不应响应或学习。

**典型案例**：VELAFORCAR-7153 / 7156 / 7157 / 7158

**排查思路**：
1. 检查 ARP 输入处理是否验证 Hardware Type 和 Protocol Type
2. 修复方向：在 ARP 输入入口增加类型校验

## 6. ARP 老化后仍响应 ICMP

**特征**：ARP 老化超时后，向 DUT 发 ICMP 请求，DUT 仍然响应

**原理**：可能是 ICMP 请求中的源 MAC 触发了 ARP 条目重新刷新（IP 包中学习 ARP 的功能）。

**典型案例**：VELAFORCAR-12887

**排查思路**：
1. 检查 ARP 条目最大存活时间配置
2. 检查 ARP 老化定时器是否正常运行
3. 检查"从 IP 包中学习 ARP"功能是否启用——如果启用，ICMP 请求本身会刷新 ARP 条目

## 7. 上电首次 TCP 建联延迟 1-2s

**特征**：上电后首次 TCP 建联延迟约 1-2 秒，后续连接正常

**原理**：上电后首次通信需要 ARP 解析对端 MAC 地址。如果首次 ARP 请求丢失（PHY 刚 link up，Switch 转发表未建立），需要等待 ARP 重试。

**典型案例**：VELAFORCAR-13007

**排查思路**：
1. 检查 ARP 请求间隔配置
2. 检查 ARP 最大重试次数
3. 检查上电后 PHY link up 到 Switch 转发表建立的时间差
4. 抓包确认首次 ARP 请求是否被 Switch 丢弃

**修复方向**：
- 减小 ARP 请求间隔加快重试
- 在 PHY link up 后主动发送 gratuitous ARP 预热 Switch 转发表
- 或在应用层增加连接重试逻辑，容忍首次延迟
