## 1. PTP 时钟精度异常（软件授时 vs 硬件授时）

**特征**：gPTP time master 在高负载下偶发时钟精度异常

**原理**：软件授时和硬件授时的精度特性完全不同：

| 授时方式 | 典型精度 | 影响因素 |
|---------|---------|---------|
| 硬件授时（PTP 硬件时间戳） | ~200us | 硬件精度，几乎不受 CPU 负载影响 |
| 软件授时（软件定时器） | ~1ms | CPU 负载、中断延迟、调度延迟 |

高负载下软件授时精度下降是预期行为，需要明确当前使用的是哪种授时方式。

**典型案例**：VELAFORCAR-16825

**排查思路**：
1. 确认授时方式：检查 PTP 相关配置和实际使用的时间戳获取接口
2. 如果是软件授时 → 高负载下精度下降是预期行为
3. 需要确认设计精度指标
4. 偏差在设计指标内 → 关闭（设计预期）；超出 → 需要优化

## 2. PTP 报文头字段与规范不一致

**特征**：gPTP 报文中的头字段值与 IEEE 802.1AS 规范不一致

**原理**：配置工具生成的宏定义值未同步规范更新。

**典型案例**：VELAFORCAR-16445 / 16451 / 16452 / 16531

**排查思路**：
1. 读取生成的 PTP 报文头字段配置宏定义
2. 对比 IEEE 802.1AS 规范要求的值
3. 不一致 → 更新配置工具模板

## 3. PTP 跨核 MMIO 访问失败

**特征**：非 MAC 部署核读取 PTP 时间失败或返回无效数据

**原理**：PTP gettime 接口直接读取 MAC 硬件寄存器（MMIO）。非 MAC 部署核访问时可能因缺少 MMIO 映射或锁保护而失败。

**排查思路**：
1. 确认 PTP 时钟读取的核是否是 MAC 部署核
2. 检查 PTP gettime 实现是否有 spinlock 保护
3. 检查非 MAC 核是否有 MAC MMIO 区域的访问权限（MPU/MMU 配置）
4. 检查是否有跨核 PTP 时钟代理机制

**修复方向**：
- 提供跨核 PTP 时钟读取接口（通过 RPMSG 或共享内存）
- 或在 MAC 部署核提供 PTP 时钟代理服务
- 或为非 MAC 核配置 MMIO 只读访问权限 + spinlock 保护

## 4. PTP TX 时间戳偶发丢失/Follow_up 缺失

**特征**：PTP master 偶发 Sync 报文后无 Follow_up，或 Follow_up 中时间戳为 0/异常值

**原理**：PTP TX 时间戳获取流程中，如果"设置待处理包指针"操作不在锁保护范围内，并发访问者可能看到旧值，导致时间戳丢失或内存泄漏。

**典型案例**：VELAFORCAR-15506

**排查思路**：
1. 检查 PTP pending 函数中"包指针赋值"是否在锁保护范围内
2. 检查所有并发路径对该指针的访问是否都持有锁
3. 检查"启动 timeout work"与"设置包指针"的顺序（应先设置再启动）

**修复方向**：
- 将包指针赋值移到锁释放之前
- 或将所有相关操作都放在锁保护范围内
