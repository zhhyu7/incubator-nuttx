## 1. 休眠唤醒后网络异常

**特征**：负载工况下休眠唤醒后，偶发 VLAN 不通、DoIP 初始化失败、ICMP/MiRT/TCP 全异常（出现 3+ 次：14173/14640/15358，均为严重/紧急）

**排查步骤**：
1. 检查唤醒后网络初始化顺序（PHY link up → ENET 驱动恢复 → 协议栈恢复 → 应用层恢复）
2. 检查 PHY 唤醒后 link up 时间（某些 PHY 需要几百毫秒到几秒）
3. 检查 ENET 驱动的 resume 函数是否正确恢复了 DMA 描述符和中断
4. 检查 IOB 状态（休眠前分配的 IOB 唤醒后是否仍有效）
5. 检查 ARP 缓存（休眠期间对端 ARP 可能已过期，唤醒后需要重新解析）
6. 检查 ethsm 的状态恢复（VLAN channel 是否正确重新打开）

**关键经验**：
- 休眠唤醒后的网络问题通常是初始化时序问题，而非协议栈逻辑 bug
- 需要设备侧日志确认唤醒后各模块的初始化顺序和时间
- Agent 对此类问题的独立分析能力较弱（需要设备侧实时数据）

## 2. 休眠唤醒卡在 can oflush

**特征**：休眠唤醒过程中 5ms 周期任务阻塞在 CAN oflush（14209）

**排查步骤**：
1. 检查 CAN 设备 flush 操作是否在等待 TX 完成但总线已断开
2. 检查休眠路径上是否有超时保护 -- flush 应设置最大等待时间
3. 检查 CAN 控制器在休眠前是否正确进入 sleep/stop 模式
