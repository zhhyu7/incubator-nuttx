## §1 ETH2CAN 周期满载下丢帧

**特征**：ETH2CAN 周期满载时 CAN3 较多丢帧，CAN1 偶发丢帧，P0 级别（15968）

**排查步骤**：
1. 检查 CAN TX mailbox/FIFO 是否被写满 -- 满载时发送速率超过总线速率
2. 检查 CAN 报文对应的 IOB 池配置是否足够（从 .config 中搜索 IOB 相关项确认）
3. 检查路由转发任务优先级是否低于其他高优先级任务导致调度延迟
4. 对比不同 CAN 通道的 TX 错误计数（`ifconfig canX`）

**关联配置**：
- CAN 报文对应的 IOB 池大小配置
- 单路 socket 发送缓冲区限值配置
- 路由转发任务优先级

## §2 eth2can 路由时延超标

**特征**：全量通信负载下 eth2can 路由时延超过 1.5ms 指标（15419）

**排查步骤**：
1. 用 trace 分析路由路径各阶段耗时：ETH 收包 → 路由查表 → CAN 发送
2. 检查是否有优先级反转 -- 路由任务被低优先级任务间接阻塞
3. 检查 IOB 分配是否因池不足导致等待
4. 对比 BMP 和 AMP 模式下的时延差异

**路由路径分析**：
```
ETH RX 中断 → 工作队列 → 网络设备输入 → IP 转发/路由查表
  → CAN 网络设备 → CAN 发送 → 驱动 transmit
```

**关键指标**：
- ETH RX → 路由查表：应 < 0.5ms
- 路由查表 → CAN TX 完成：应 < 1.0ms
- 总时延指标：< 1.5ms

## §3 双向打流后 CRR 报文断流

**特征**：双向打流 7 分钟后 CRR 报文断流且无法恢复（15788）

**排查步骤**：
1. 检查 IOB 池是否耗尽 -- 长时间打流可能导致 IOB 泄漏
2. 检查 CAN TX 队列是否死锁 -- 发送回调是否正确释放了 IOB
3. 用 `cat /proc/iob` 监控 IOB 使用量随时间的变化趋势
4. 检查是否有错误帧导致 CAN 控制器进入 bus-off 状态

**根因模式**：
- IOB 泄漏导致池耗尽 → 所有路由报文无法分配 IOB → 断流
- Bus-off 后未自动恢复 → 该通道永久停止发送

## §4 CAN2ETH sequence_num 累加错误

**特征**：CAN2ETH 报文 NTSCF_Header.sequence_num 跳过了 95（15985）

**排查步骤**：
1. 检查 sequence_num 计数器是否为全局变量且多任务并发访问未加锁
2. 检查是否存在整数溢出或类型截断（uint8_t vs uint16_t）
3. 抓包对比源端 CAN 帧序号和目标端 ETH 帧中的 sequence_num

**关联代码**：
- ieee1722acf 打包逻辑中的 sequence_num 累加
- NTSCF Header 结构体定义

## §5 CAN2ETH / ETH2HOST 少量丢帧

**特征**：BMP 架构下 CAN2ETH 和 ETH2HOST 均存在少量丢帧（15773/16182）

**排查步骤**：
1. 检查 IOB 池容量是否在峰值负载下不足
2. 检查 BMP 模式下跨核 rpmsg 通道缓冲区是否足够
3. 对比 AMP 模式是否同样丢帧 -- 区分 BMP 特有问题还是通用问题
4. 检查 TX 完成回调中 IOB 释放是否及时

**BMP 特有因素**：
- 跨核 rpmsg 通道带宽限制
- 全局 IOB 池多核共享竞争
- 中断处理延迟（多核调度开销）

## §6 CAN2ETH ACF rsv 字段错误

**特征**：CAN2ETH 路由 AVTP 报文中 ACF CAN rsv 字段应为 0 但部分报文为 1（OS4ECU-461）

**排查步骤**：
1. 检查 ieee1722acf 打包逻辑中 rsv 字段是否正确清零
2. 检查结构体是否有未初始化的 padding 字节
3. 用抓包工具对比正常帧和异常帧的完整二进制内容

**修复方向**：
- 结构体初始化时 memset 清零
- 或在填充 ACF header 时显式设置 rsv = 0

## §7 路由目标网段周期波动超标

**特征**：ETH-CAN/CAN-CAN 路由目标网段报文周期波动超 10% 阈值，疑似路由阻塞（13041/13040）

**排查步骤**：
1. 用 CANoe trace 分析目标网段报文的实际周期分布
2. 检查路由转发任务是否被更高优先级任务抢占导致延迟
3. 检查 CAN TX 队列排队深度 -- 多路路由报文共享 TX 队列时可能互相影响
4. 检查是否存在同一目标网段连续两帧 RX 报文的批量发送现象

**分析方法**：
- 统计报文间隔的标准差和最大偏差
- 对比有/无其他负载时的周期稳定性
- 检查路由任务的调度 trace（是否有长时间未被调度的间隙）
